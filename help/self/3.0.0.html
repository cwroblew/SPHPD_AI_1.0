Help on Help: Section 3.0.0

 

Section 3.0.0: Understanding Keyword Search

The built-in keyword search is simple in nature. You enter a keyword in the embedded Web form in the help pages and the help application searches existing the keyword index files for all the sections to locate the pages matching the keywords.

If you wish to offer keyword search in any of your applications directly, you can embed a Web form such as below in your application interface: 

<form>
  <input type=text name="keyword">
  <input type=submit value="Find">
  <input type=hidden name="app" value="your_application_name">
</form>
The name of your application must match what you have used in $APP_HELP_MAP in help.conf.

For example, if your map file has $HELP_DIR set to help/myapp and ROOT_PATH in help.conf set to %DocumentRoot% then you need to create the help contents in %DocumentRoot%/help/myapp directory.

Performing Search via URL

You can also specifiy an URL with specific keywords and application name to directly search for the keywords in your application's keyword index cache. Here is the URL syntax:

http://yourserver/help/apps/help.php?app=application_name&keyword=keyword_list

For example, to find matches for keyword "built-in" in the help for an application called "self" you can enter: 
http://yourserver/help/apps/help.php?app=self&keyword=built-in

For example, to find matches for both "built-in" and "nature" in an application called "self" you can enter: 
http://yourserver/help/apps/help.php?app=self&keyword=built-in+AND+nature
Notice how the AND operator is added using + signs. The + sign in URL represent white space.


Search Limitations

Currently, the help search cannot search multiple applications at time. This means you cannot supply two or more application names in the search to perform keyword search. This is not needed for most scenarios as applications usually have separate help contents.
