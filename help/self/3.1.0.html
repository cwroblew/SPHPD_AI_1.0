Help on Help: Section 3.1.0

 

Section 3.1.0: Creating Keyword Index Cache

Before you can perform keyword search, you need to create keyword index cache. The makeindex.php application generates index for all applications named in $APP_HELP_MAP in help.conf file.


Prerequisites of Making Index

You have to make sure that the help directory where the help contents are located is writable by the Web server. For linux and Unix platform you can the following commands in $HELP_DIR for each application: 
chown -R webserver_user:webserver_group help_directory
chmod -R 700  help_directory


For example, the help system's self help contents is located in the %DocumentRoot%/help/self directory. Say this is really /www/help/self directory on your Apache server running under user and group ID: httpd. In such case you can run: 
chown -R httpd:httpd  /www/help/self
chmod -R 700  /www/help/self

This will make sure that the /www/help/self is only readable and writable by the Web server itself. Of course, if you wish to be able to edit the contents, you will need to modify the above commands to allow appropriate user to create/modify help contents. For example, say you use a group called webdev for all web development work, in such case you can use: 
chown -R httpd:webdev  /www/help/self
chmod -R 770  /www/help/self
Here the sample help directory /www/help/self is now has read, write, execute permission for user httpd (for Apache) and group webdev (the help contents developers).


Running index cache application

Once you have ensured that the help directories for all your applications are writable by the Web server you can run the index generation application, makeindex.php, as follows: 
 http://yourserver/help/apps/makeindex.php

If you wish to limit the index generation to a single application, run the script with app[]=application_name parameter. For example: 
 http://yourserver/help/apps/makeindex.php?app[]=self&app[]=irm

Here the index will be generated for two applications named "self" and "irm".


Restricting Access to Index Generation

The index generation script should be only run when the help contents are updated. There is no need to run the application by end-users. You can restrict access to the application by providing an IP address/network based access restrction configuration using the following configuratino parameters found in help.conf file: 
   define('ACL_ALLOW_FROM', '0.0.0.0');
   define('ACL_DENY_FROM',  '');

Here the first parameter ACL_ALLOW_FROM can be used to specify one or more IP or network addresses that are allowed access to the makeindex.php application. The ACL_DENY_FROM is allowed to deny access to one or more IP or network addresses. The above configuration states shows ACL_ALLOW_FROM set to 0.0.0.0, which is the IP universe or all networks and ACL_DENY_FROM list is empty. This configuration means "allow access from anywhere and deny none".
Now to restrict access to all but a single IP address you can configure the above two parameters in help.conf as follows: 
   define('ACL_ALLOW_FROM', '192.168.0.10');
   define('ACL_DENY_FROM',  '0.0.0.0');

Here all but the 192.168.0.10 IP address is allowed access.

To allow any hosts from a network 192.168.0.x to access the makeindex.php application you can use: 
   define('ACL_ALLOW_FROM', '192.168.0');
   define('ACL_DENY_FROM',  '0.0.0.0');

You should allow only the hosts you want and deny everyone else by using 0.0.0.0 for ACL_DENY_FROM.


Troubleshooting Index Generation

If you run makeindex.php application and notice that it shows failure for certain sections or applications, you need to investigate the following:

  • Directory/File permission settings - make sure that the help directory for your applications are writable by the Web server.

  • Help map configuration - if you notice that some sections are failing to get indexed, make sure these sections exist in the help directory. Also, make sure your $SECTIONS map in the map file for the application is matching the number of sections you actually have in the help directory.
